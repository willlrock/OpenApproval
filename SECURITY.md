# Безопасность

Проект находится в beta. Отдельного срока поддержки версий пока нет;
исправления готовятся для текущей ветки разработки. Перед обновлением
сохраняйте проверенную резервную копию базы и private storage.

## Сообщение об уязвимости

Не публикуйте уязвимость, рабочие токены или документы в обычном issue.
На странице **Security → Advisories** репозитория используйте **Report a
vulnerability**, если приватные сообщения включены владельцем. Если кнопки
нет, создайте issue только с просьбой предоставить приватный канал связи,
без описания уязвимости и данных для её воспроизведения.

В приватном сообщении укажите версию/коммит, условия, шаги воспроизведения
на вымышленных данных, влияние и возможное исправление. Проверяйте только
свою установку или среду, для которой у вас есть разрешение.

## Эксплуатация

- Храните `.env`, ключи и резервные копии вне публичного webroot и Git.
- Webroot должен указывать на `public/`; private storage не раздаётся nginx.
- Для production используйте HTTPS, `APP_DEBUG=false`,
  `SESSION_SECURE_COOKIE=true` и явный список `TRUSTED_PROXIES`.
- Telegram webhook защищается отдельным `TELEGRAM_WEBHOOK_SECRET`.
- Создавайте администратора через `admin:bootstrap`; общих паролей нет.
- После утечки отзовите соответствующий ключ у его провайдера.
  Удаление строки из текущего файла не удаляет её из истории и копий.

Инструкция: [самостоятельное развёртывание](docs/self-hosting.md).
